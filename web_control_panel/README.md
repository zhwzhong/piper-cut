# Web Control Panel

这个目录是网页控制面板，不修改现有检测和机械臂控制脚本，只调用项目根目录里的入口：

- `01_detect_seam_start_to_base.py`
- `02_read_probe_tip_pose.py`
- `03_move_to_probe_tip_point.py`
- `04_move_to_probe_tip_pose.py`
- `05_restore_sdk_control_mode.py`

## 在 Radxa 上启动

```bash
ssh radxa-wg
# 或 ssh radxa@10.77.0.3

cd /home/radxa/Desktop/piper_sdk_seam_probe_bundle_20260821
/home/radxa/box_sdk_env/bin/python web_control_panel/server.py --host 0.0.0.0 --port 8080
```

浏览器打开：

```text
http://10.77.0.3:8080
```

如果只想通过 SSH 隧道访问：

```bash
ssh -L 8080:127.0.0.1:8080 radxa-wg
```

然后本机浏览器打开：

```text
http://127.0.0.1:8080
```

## 页面功能

- `参数说明`：把 ROI、mask mode、显示开关、运动安全参数和按钮含义打印到页面下方日志框。
- `一键执行`：网页前端按 `检测中线 -> 恢复 SDK 模式 -> 移动到保存点位 point_2 -> 到起点 -> 到终点` 分步执行；如果勾选 `启用分段`，最后一步会拆成多段执行。默认 dry-run，真实运动仍需要 `允许运动`。执行前需要已经保存名为 `point_2` 的点位。
- 打开页面后默认显示实时视频流，视频以压缩 MJPEG 传输，便于浏览器低延迟查看。
- `实时视频`：打开/关闭实时相机画面。
- `清晰度`：控制实时 MJPEG 的 JPEG 质量和帧率。`流畅` 带宽低、延迟小；`标准` 为默认；`高清` 和 `超清` 更清楚但延迟和带宽更高。
- `ROI`：控制实时视频里是否显示蓝色 ROI 框、像素坐标原点和 x/y 方向。
- `箱子`：控制实时视频里是否显示最后一次检测得到的箱子上表面外接框。需要先点击一次 `检测中线`。
- `中线`：控制实时视频里是否显示最后一次检测得到的中线。需要先点击一次 `检测中线`，否则没有可显示的中线结果。
- `mask mode`：默认 `rgbd`，即彩色图和深度图一起用于箱子区域分割。
- `Z最小 mm`：全局 TCP 目标 Z 下限，默认 `99 mm`。检测中线、手动校准、移动到 XYZ、回到点位、到起点/终点、分段运动、A-F 和方向点动都会使用同一个值；如果某个待发送目标的 Z 小于该值，后端会把实际发送的 Z 改为这个最小值，并在返回结果里标记 `z_clamped=true`。
- `启用分段`：控制从起点到终点是否拆段执行，默认开启。关闭后 `到终点` 和 `一键执行` 会一次性移动到终点。
- `分段 mm`：启用分段时，从起点到终点的最大插值段长，默认 `30 mm`。系统会把 start/end 拆成多段，每段执行成功后才继续下一段；某段失败会停止并显示 `stopped_at`。
- `拍摄 ROI`：保存并显示一张当前相机画面和 ROI 标注。
- `检测中线`：重新拍摄当前 RGB-D 画面，用当前 ROI 调用中缝检测，显示 overlay，并输出起点/终点 TCP 坐标。检测完成后会缓存中线像素坐标，实时视频里默认显示中线，并把起点/终点像素坐标填入 `线段起点/终点 px`。
- `线段起点/终点 px`：默认显示最近一次检测或手动调整后的中线像素端点。
- `选择线段`：在图像上先点线段起点、再点线段终点，直接重建整条中线，并重新生成后续运动使用的目标 JSON。
- `应用线段`：手动修改 `线段起点/终点 px` 四个输入框后，把该线段写回检测结果，并重新生成后续运动使用的目标 JSON。
- `三线切割`：在当前中线基础上自动生成三条切割线，用于把胶带两端也切开。左边线段端点为 `A/B`，中间线段为 `C/D`，右边线段为 `E/F`。
- `端部线 px`：左右端部短线的像素长度，默认 `90 px`。如果端部胶带更宽，可以适当调大；如果短线超出箱面或深度不稳定，应调小。
- `生成三线`：检测中线后手动生成三条切割线并显示 overlay，不发送机械臂运动命令。生成后可在 `三线点位` 下拉框选择 `A-F` 任一点，并点击 `到选中点` 移动过去。
- `一键 A-F`：生成三线后，先移动到保存点位 `point_2`，再按 `A->B -> B->C -> C->D -> D->E -> E->F` 连续执行；使用当前 `启用分段` 和 `分段 mm`。
- 三线模式下的 `一键执行`：按 `A->B -> B->C -> C->D -> D->E -> E->F` 连续执行；如果勾选 `启用分段`，相邻两点之间都会按 `分段 mm` 插值分段执行。
- `校准起点`：先点击按钮，再在视频画面里点新的中线起始点。系统会保持原检测线的方向和长度，把整条中线平移到新的起点，并重新生成后续运动使用的 `probe_tip_targets_base_manual_*.json`。
- `校准终点`：先点击按钮，再在视频画面里点新的中线终点。系统会保持原检测线的方向和长度，把整条中线平移到新的终点，并重新生成后续运动使用的目标 JSON。
- `获取 TCP 坐标`：读取当前 TCP 尖端坐标和姿态，并把当前 X/Y/Z 自动填入 `移动到 XYZ` 的三个输入框。
- `拍摄标定板`：停止实时视频，保存一张静态 RGB-D 快照，并显示带 ROI 的图像，用于后续点击验证点。
- `选择验证点`：在静态图像上点击标定板角点或标记点。后端读取同一帧 `depth_mm.png` 和 `camera_info.yaml`，结合 `eye_to_hand_extrinsics.yaml`、`depth_correction.yaml`，生成该点在 `base_link` 下的目标坐标。
- `计算误差`：读取当前 TCP 尖端坐标，与上一次选择的验证点坐标相减，输出 `dx/dy/dz`、XY 误差、3D 误差和 Z 误差。
- `运动模式`：控制 `回到点位`、`到起点`、`到终点` 和 `一键执行` 内部移动步骤。默认 `moveP` 点到点，适合当前只跑流程不真实切割；`moveL` 是 TCP 直线运动，后续真实贴近中线切割时再切换使用。
- `移动到 XYZ`：三个输入框默认显示当前 TCP 尖端坐标。你可以修改 X/Y/Z 中的任意值，单位 mm；后端会保持当前 TCP 姿态，只替换 X/Y/Z，再调用 `04_move_to_probe_tip_pose.py` 移动到该点。
- `点位名称`：输入要保存的任意点位名称，例如 `A`、`B`、`start_safe`、`切割前等待点`。
- `保存点位`：读取当前 TCP 尖端位姿、原始法兰位姿和 6 个关节角，并按点位名称保存到 `config/saved_poses/<点位名称>.json`。
- `回到点位`：从下拉框选择任意已保存点位，并调用 `04_move_to_probe_tip_pose.py` 移动回该点位，默认 dry-run。
- `清除点位`：删除下拉框当前选择的点位 JSON 文件，不发送机械臂运动命令。删除 `origin` 时也会删除兼容文件 `config/far_pose.json`。
- `到起点`：移动到当前中线起点，默认 dry-run；发送前同样应用 `Z最小 mm`。
- `到终点` / `分段到终点`：关闭 `启用分段` 时一次性移动到终点；开启时读取当前中线 start/end，根据 `分段 mm` 插值成多个 TCP 目标，逐段调用 `04_move_to_probe_tip_pose.py`。每段完成并返回 OK 后才发下一段，失败即停止。
- `恢复 SDK`：默认只检查状态；勾选允许运动后才发送恢复命令。
- `X/Y/Z` 点动：方向键控制的是 TCP 尖端坐标，不是单独关节。按下按钮后后端启动连续点动线程，以约 100 Hz 持续发送 TCP 目标；网页每 120 ms 发送一次保活，松开按钮立即停止。默认步长 `1 mm`、步频 `80 ms`，换算连续速度约 `12.5 mm/s`，速度比例默认 `5%`；不勾选 `允许运动` 时只 dry-run。

页面显示的相机图和 overlay 是压缩 JPG 预览，便于网页传输；原始 `color.png`、`depth_mm.png`、`center_seam_overlay_*.png` 和坐标 JSON 仍保存在 `outputs/`。

实时视频不会每一帧重新跑中缝检测。它只显示最后一次 `检测中线` 的箱子框和中线结果，这样画面不会卡顿，也不会让相机和检测脚本频繁抢资源。`拍摄标定板` 使用干净预览，只显示 ROI 和后续选择的验证点，不叠加箱子框、中线或 A-F 端点；后续点击 `检测中线` 或 `一键执行` 会重新拍摄当前箱子画面，不会复用标定板快照。

手动校准不是只改显示图。它会复制最后一次 `center_seam_result_*.yaml`，根据你选择的起点或终点平移整条线，再调用 `seam_to_probe_tip_targets_sdk.py` 重新生成 base 坐标。校准后再点 `到起点` / `到终点`，使用的是校准后的目标 JSON。

执行 `拍摄 ROI` 或 `检测中线` 时，前端会先断开实时视频，命令结束后再自动恢复视频流。`一键执行` 中只有检测阶段会短暂停止视频，检测完成后会先恢复实时画面，再继续 SDK 恢复和机械臂运动步骤。方向键点动和移动命令不抢相机，只调用机械臂 TCP 控制接口。

标定验证推荐流程：

1. 把标定板放到相机视野内，点击 `拍摄标定板`。
2. 点击 `选择验证点`，在静态图像上点一个角点或清晰标记点。
3. 页面会输出该点在 `base_link` 下的目标坐标。
4. 使用方向键把探针尖端低速移动到该物理点。
5. 点击 `计算误差`，查看当前 TCP 与视觉换算目标之间的误差。

## 安全逻辑

页面默认勾选 `允许运动`，网页会自动向后端传入确认词。真实运动必须满足：

1. 页面勾选 `允许运动`。
2. 后端脚本再次向现有 CLI 传入 `--execute --confirm EXECUTE`。

恢复 SDK 模式使用单独确认词 `RESTORE_CONTROL_MODE`，页面会在点击恢复按钮时自动传入。

任意点位的推荐用法：

1. 手动或点动把 TCP 尖端移动到目标位置。
2. 在 `点位名称` 输入一个名字，例如 `A`。
3. 点击 `保存点位`。
4. 以后从下拉框选择 `A`，点击 `回到点位`。

`回到点位`、`到起点` 和 `到终点` 使用同一套安全逻辑：不勾选 `允许运动` 时只 dry-run；勾选后网页会自动发送确认词，并按页面选择的 `运动模式` 执行。
